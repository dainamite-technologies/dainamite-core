## Summary

Counts: 0 blocker, 2 major, 3 minor, 3 nit.

Checked and found clean:
- **I-13 check order (answer):** 404 → QUOTE_CLOSED → QUOTE_CONVERTED → COST_PLUS_DISABLED → LINE_NOT_ELIGIBLE → superseded → noop → conflict → not_open. All checks run in `shortCircuit` under the quote's PESSIMISTIC_WRITE lock, so refusals and the noop write nothing and do not bump the revision.
- **Concurrency:** two concurrent answers, and answer vs re-request, serialize on the aggregate row.
- **Idempotency:** a retry after a proposal or after apply is a noop, because the hash is kept and `knownRef` uses the proposal ref. A stale id after a re-request or R1b is superseded. The validUntil-in-past check runs after the noop check.
- **Locked quotes (R11 / I-5):** a locked answer or decline never reprices (`reprice = !locked`). The margin-only exemption is consistent between `classifyAnswer` and `declineEffect`.
- **Conversion:** COST_ANSWER_PENDING is checked before COSTS_NOT_CONFIRMED, and conversion cancels requests in the same transaction.
- **Apply-answer:** sets status → ready and applies the value in one write, with `expectedRevision` and the mutation guards.
- **Cancellation paths:** quote status close, CPQ DELETE (now under the lock, with guards and openApi), conversion, manual value (also clears the proposal), line removal (removeQuoteLineTree, ARC cancel, target detach), R1a/R1b, re-request and clone reset all cancel in the same transaction, append history (capped at 50, no amounts) and emit one signal. Exception: manual-cost DELETE (finding #2).
- **Events:** published only from `afterCommit`, never on rollback or shortCircuit. Requested / cancelled events are de-duplicated by request id. All three events are `clientBroadcast: false` and carry no amounts.
- **Notifications:** the notifications module is an optional peer. Recipients need view + manage through `rbacService` (wildcard-aware) and must belong to the quote's organization. No amounts.
- **Confidentiality (I-4):** the redacted projection carries statuses only. Apply-answer redacts its response for callers without cpq.costs.view. Queue list has no amounts; queue detail requires costs.view. Every new route uses `requireFeatures`, never `requireRoles`.
- **DB constraints:** `value_origin 'supplier'` is covered by Migration20261115000100 (its down() is correct). No other CHECK constraint on the written columns. The queue index matches the query.
- **Tenant scoping:** all new queries are scoped and filter `deletedAt`, except the moved delete-quote reads (finding #6).
- **Workflow seed:** seeded disabled, grant limited to cpq.costs.view and cpq.costs.manage, provisioned tenant-scoped. CALL_API paths and bodies match the answer and decline schemas; single-placeholder interpolation keeps the number type.
- **UI:** uses `apiCall`, lucide icon, `t(key, fallback)`, Cmd/Ctrl+Enter plus the Radix Escape, and DataTable pagination with pageSize ≤ 100.
