## 2026-11-15T18:00:00Z — step 13 scope decisions
- Lock order as built for re-confirmation: pre-read of the order row (unlocked, outside the transaction, only for the immutable `source_quote_id`), then ONE forked transaction: `lockSourceQuote` FIRST, then the order row read WITHOUT a lock (`refresh`), then the cost / line. It never locks the order row, so it cannot invert activation's order (order row -> quote -> subscriptions); once it owns the quote lock the order status it reads is the one activation committed (`409 ORDER_ACTIVATED`, nothing written).
- Route `PATCH /api/cpq/orders/{orderId}/costs/{orderLineCostId}` (`cpq.orders.manage` + `cpq.costs.manage`). Value semantics: margin only (`total_amount`, never `charges` / totals). A changed value (amount or currency) needs a NEW `supplierQuoteRef` or a `note`: I used `422 NOTE_REQUIRED` for it (the spec lists only `CURRENCY_NO_RATE` / `VALIDITY_EVIDENCE_REQUIRED`; this extra code mirrors the quote cost route). A foreign value without a rate is refused (`422 CURRENCY_NO_RATE {from,to}`), never stored as `none`. Status becomes `confirmed` when an amount exists; `value_origin` becomes `manual` only if the value changed; `origin` (catalog / carried) never changes. Statuses other than draft / pending_activation: cancelled -> `ORDER_CANCELLED`, anything else (active, fulfilled) -> `ORDER_ACTIVATED`.
- `QUOTE_CONVERTED` bodies of the five sourcing writes now carry `{orderId, orderLineCostId}` (null when the cost line has no order copy).
