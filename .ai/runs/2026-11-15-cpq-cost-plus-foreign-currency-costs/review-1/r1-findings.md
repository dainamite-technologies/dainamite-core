## Summary

Counts: 0 blocker, 0 major, 5 minor, 4 nit.

Checked clean (verified against the code):
- **Conversion math.** Checked `convertedAmount` (costPlusPrice), `costLineTotal` / `costAcc` (quoteMargin), `convertedInstanceAmount`, the preview `costTotal`, `orderCostCopy` totals and `costValueView`. Each converts at full precision and rounds once; 300 x 0.92 x 1.25 = 345. Item, asset and inventory margins read the already converted `totalAmount`. `toCostLineValue` carries `fxRate` on both the locked path and the plan path, and `cpqPricingService` passes it to `computeCostPlusPrice`. The order margin view passes `fxRate`. `margin_hash` includes fx, and the Q15 characterization hash is pinned.
- **No 1:1 path in the writers.** Catalog `foreign()`, `createCost` / `updateCost` (`fxPatch`, also with no resolver wired), `valuePatch`, `enteredFxPatch`, the calculate-price contexts and the preview all leave a foreign value without a rate as `none` + CURRENCY_NO_RATE. The only residual weak shape is finding #1.
- **Snapshot policy.** Locked and ordered quotes return before `planQuoteCosts` (`resolveQuoteCosts` / `resolveCostPlusInputs`). With `save=false` the plan stays in memory. Carried lines and ARC mirror lines reuse their stored snapshot. Under R11, `affectsPrice` treats a currency change as price-affecting, and none->confirmed on a locked price-basis line is refused. A same-value confirmation keeps the snapshot (`needsSnapshot` excludes a locked price-basis line). A locked margin-only line re-rates. Q13 none->estimated plus note is applied.
- **Resolver.** It passes `autoFetch: false`. Look-back is clamped 0-30 (default 7). Source priority comes first, then the only row, then `source` ascending. Inverse is used only when there is no direct rate, at 8 dp, and a rate that rounds to zero is rejected. It never throws. The memo key is tenant|org|pair|day. The DI container is per request (`createRequestContainer` calls `register(container)` each time) and the resolver is `.scoped()`, so no memo leaks across requests or tenants. `getRate` is called with a UTC-midnight date, which is never in the future.
- **Optional currencies.** The service is used through `hasRegistration('exchangeRateService')` and a structural interface. There are no imports of the currencies module inside the CPQ package; only the L3 demo seed imports `ExchangeRate`, and `currencies` is enabled in src/modules.ts.
- **Migrations.** They are additive nullable text columns with a symmetric down(). No CHECK constraints are touched; `value_status` values stay within the existing check. The `missingFxPairs` raw SQL is parameterized and tenant/org scoped, joins with a scope match, filters soft deletes, excludes closed statuses and quotes that already have an order, and the columns exist. Copies to order and inventory are verbatim, inventory no-op detection covers the fx fields, and the adjustment clone copies the fx fields.
- **Confidentiality (I-4).** The redacted quote, order and inventory views have no fx fields. cost-preview requires `cpq.pricing.view` + `cpq.costs.view` (unchanged). The usage route requires `costs.view`. calculate-price exposes no fx (the test asserts rate and source are absent). Audit and signal payloads are amount-free. The resolver log has no amounts. CostFxHint is gated on a server feature check.
- **demo_gix seed.** Columns match the `ExchangeRate` entity. Dates are UTC midnight. It is idempotent on the unique (org, tenant, pair, date, source) and tenant/org scoped.
- **UI.** It uses apiCall, `t(key, fallback)` and the `SimpleTooltip` primitive. Order and inventory values are shown in the document currency when a rate applies. Dialog key handling is untouched.
- **E2E TC-CPQ-COST-FX-001.** It runs against the real routes, sources sort ahead of real providers, and cleanup is present. It does not assert the price (finding #5).
